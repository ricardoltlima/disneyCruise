AWS Certified Developer Associate DVA-C02

This page turns the uploaded course PDF into a readable certification roadmap. It follows the PDF topics, explains the ideas in plain language, and connects them to the current DVA-C02 exam domains.

DVA-C02 Overview

The AWS Certified Developer Associate exam validates that you can build, secure, deploy, and troubleshoot cloud applications using AWS services. It is not only a memorization exam. It tests whether you can choose the right developer-focused service and understand how the pieces work together.

What the PDF Covers

The PDF table of contents starts with foundations, IAM, EC2, storage, networking, S3, SDKs, then moves into CloudFront, containers, Elastic Beanstalk, CloudFormation, messaging, monitoring, Lambda, DynamoDB, API Gateway, CI/CD, SAM, CDK, Cognito, advanced identity, encryption, and exam prep.

How to Read This Page

Use the PDF as the slide source and this page as the explanation layer. For every topic, ask: what problem does this solve, when would I use it, how does a developer interact with it, and what mistake would the exam try to catch?

The Developer Mindset

A Solutions Architect thinks heavily about broad architecture. A Developer Associate thinks more about building and operating application code on AWS. That means SDK calls, permissions, service integrations, event flows, deployment pipelines, observability, retries, errors, and security boundaries.

Exam Facts to Remember

  • The current DVA-C02 exam has 50 scored questions and 15 unscored questions.
  • You have 130 minutes.
  • The passing scaled score is 720 out of 1000.
  • You do not need to pass every domain separately; the exam uses a compensatory scoring model.
  • The current DVA-C02 domains are Development with AWS Services, Security, Deployment, and Troubleshooting and Optimization.

Exam Domains

The official DVA-C02 exam guide organizes the exam into four weighted domains. The PDF topics map into these domains.

1. Development with AWS Services - 32%

This is the largest domain. Expect Lambda, DynamoDB, API Gateway, SDK usage, S3, event sources, application integration, and service-specific behavior.

Study lens: how does application code call, configure, retry, and integrate with AWS services?

2. Security - 26%

IAM, roles, resource policies, Cognito, KMS, Secrets Manager, encryption, signed requests, and secure access patterns.

Study lens: who is allowed to do what, against which resource, under which conditions?

3. Deployment - 24%

Elastic Beanstalk, CloudFormation, SAM, CDK, CodeCommit, CodeBuild, CodeDeploy, CodePipeline, containers, and safe release practices.

Study lens: how does code become a tested, deployed application?

4. Troubleshooting and Optimization - 18%

CloudWatch, X-Ray, logs, metrics, alarms, performance bottlenecks, Lambda tuning, DynamoDB capacity, API Gateway errors, and retry behavior.

Study lens: when something is slow, broken, throttled, denied, or expensive, where do you look first?

AWS Foundations

The PDF starts with AWS basics because DVA-C02 assumes you can reason about regions, availability zones, global services, regional services, and the shared responsibility model.

Regions and Availability Zones

A Region is a geographic area such as us-east-1. An Availability Zone is an isolated data center group inside a Region. Multi-AZ designs protect applications from a single data center failure.

Day-to-day analogy: a Region is a city, and Availability Zones are separate buildings in that city. If one building loses power, the other buildings can still operate.

Global vs Regional Services

  • Global: IAM, Route 53, CloudFront, WAF in many common scenarios.
  • Regional: Lambda, API Gateway, DynamoDB, S3 bucket region placement, EC2, RDS, CloudWatch logs and metrics.

Exam trap: if an application works in one Region but not another, ask whether the service, resource, key, bucket, or deployment exists in that Region.

Shared Responsibility Model

AWS secures the cloud: facilities, hardware, managed service infrastructure, and global network. You secure what you put in the cloud: IAM policies, data, application code, network rules, encryption choices, and configuration.

For fully managed services like Lambda and DynamoDB, AWS owns more infrastructure. You still own IAM permissions, code behavior, data access, encryption choices, and monitoring.

IAM and Security

Security is the second-largest DVA-C02 domain. You need to understand IAM deeply enough to debug AccessDenied errors and design least-privilege application access.

IAM Users, Groups, Roles, and Policies

User: a human or long-term identity. Group: a collection of users. Role: temporary permissions that can be assumed by AWS services, users, or external identities. Policy: JSON rules that allow or deny actions.

{
  "Effect": "Allow",
  "Action": "dynamodb:GetItem",
  "Resource": "arn:aws:dynamodb:us-east-1:123456789012:table/Reservations"
}

For applications, roles are usually better than access keys. A Lambda function should use a Lambda execution role. An EC2 instance should use an instance profile. A container task should use a task role.

Identity Policy vs Resource Policy

An identity policy is attached to a principal, such as a user or role. A resource policy is attached to a resource, such as an S3 bucket, SQS queue, KMS key, or Lambda function. Access is allowed when the relevant policy evaluation results in allow and no explicit deny blocks it.

Exam trap: S3 access might be controlled by IAM policy, bucket policy, ACLs in older setups, block public access settings, KMS key policy, and VPC endpoint policy. If access fails, check every layer.

KMS and Encryption

KMS manages encryption keys. Many AWS services integrate with KMS for encryption at rest. The developer exam often tests whether the application role has both service permissions and KMS permissions.

{
  "Effect": "Allow",
  "Action": [
    "kms:Decrypt",
    "kms:GenerateDataKey"
  ],
  "Resource": "arn:aws:kms:us-east-1:123456789012:key/key-id"
}

Secrets Manager and Parameter Store

Do not put database passwords or API keys in source code, Docker images, or plaintext environment files. Use Secrets Manager for secrets with rotation support. Use Systems Manager Parameter Store for configuration and, when appropriate, secure strings.

Cognito

Cognito helps with user authentication and authorization for applications. User Pools handle user sign-up and sign-in. Identity Pools provide temporary AWS credentials so authenticated users can access AWS resources with controlled permissions.

Simple rule: User Pool answers "who is the user?" Identity Pool answers "what temporary AWS credentials can this user receive?"

Compute and Networking

The PDF covers EC2, load balancing, auto scaling, containers, Beanstalk, Route 53, and VPC basics. DVA-C02 is developer-focused, so learn enough to deploy and troubleshoot applications without going too deep into network architecture.

EC2 Basics

EC2 gives you virtual machines. You choose instance type, AMI, storage, security groups, IAM role, and user data. Developers should know how applications use instance roles instead of storing access keys on the instance.

For DVA-C02, EC2 often appears around instance metadata, IAM roles, security groups, user data, load balancers, auto scaling, and deployment targets.

Load Balancers and Auto Scaling

A load balancer distributes traffic across healthy targets. Auto Scaling adjusts capacity based on demand or schedules. For APIs, Application Load Balancer is common because it understands HTTP routing, path routing, host routing, and target groups.

Developer angle: if users get intermittent errors, check target health, security groups, listener rules, health check path, and whether the app actually listens on the expected port.

Route 53

Route 53 is DNS. It maps names like api.example.com to resources such as load balancers, CloudFront distributions, or API Gateway custom domains. Know A records, CNAME records, alias records, hosted zones, TTL, and routing policies.

VPC Basics

A VPC is your isolated network in AWS. You should recognize public subnets, private subnets, route tables, internet gateways, NAT gateways, security groups, network ACLs, and VPC endpoints.

Exam trap: a Lambda in a VPC may lose internet access unless private subnets route outbound traffic through a NAT gateway. For private access to S3 or DynamoDB, VPC endpoints can avoid public internet routing.

Containers on AWS

The PDF includes containers because modern AWS applications often package code as Docker images. ECS runs containers using tasks and services. ECR stores container images. Fargate runs containers without managing servers.

For developer exam purposes, know the difference between image registry, task definition, task role, execution role, cluster, service, and load-balanced container deployment.

Elastic Beanstalk

Elastic Beanstalk is a platform-as-a-service layer. You upload application code and Beanstalk provisions infrastructure such as EC2, load balancer, auto scaling, logs, and health monitoring.

Think of it as a managed deployment environment for teams that want AWS to handle much of the infrastructure wiring while still allowing configuration.

Storage and Data

The PDF covers S3, RDS, Aurora, ElastiCache, and DynamoDB. For DVA-C02, DynamoDB and S3 are especially important because developers directly interact with them through SDKs and service integrations.

S3

S3 stores objects in buckets. It is not a filesystem. Each object has a key, value, metadata, version behavior if enabled, encryption settings, storage class, and access controls.

  • Versioning: keeps previous versions of objects.
  • Lifecycle policies: move or expire objects over time.
  • Pre-signed URLs: temporary URLs that allow upload or download without exposing AWS credentials.
  • Event notifications: trigger Lambda, SQS, or SNS when objects change.
  • Encryption: SSE-S3, SSE-KMS, and client-side encryption patterns.

Exam trap: public access can be blocked even when a bucket policy seems to allow access. Check S3 Block Public Access.

DynamoDB

DynamoDB is a managed NoSQL database designed for predictable low-latency access at scale. You model data by access patterns, not by normalized relational design.

  • Partition key: decides where data is stored and how it is distributed.
  • Sort key: allows multiple related items under one partition and supports range queries.
  • GSI: alternate query pattern with its own partition/sort key.
  • Conditional writes: protect correctness and idempotency.
  • TTL: expires temporary items.
  • Streams: emits item changes for Lambda or event processing.
PutItem with condition:
attribute_not_exists(idempotencyKey)

Developer exam mindset: prefer Query over Scan, design keys around queries, handle throttling, and use conditional writes for duplicate prevention.

RDS and Aurora

RDS and Aurora are relational databases. Developers should understand connection strings, IAM authentication, Secrets Manager, read replicas, Multi-AZ, backups, and connection pooling.

Exam trap: Lambda can overwhelm relational databases if it scales quickly and opens too many connections. Use RDS Proxy or control concurrency.

ElastiCache

ElastiCache provides Redis or Memcached. Use it for low-latency caching, session storage, rate-limiting counters, and expensive query results. Cache invalidation and TTLs matter.

Serverless

The PDF spends major time on Lambda, API Gateway, DynamoDB, SAM, Cognito, and other serverless services. This is central to DVA-C02.

Lambda

Lambda runs code in response to events. You manage code, configuration, permissions, memory, timeout, environment variables, and event source mappings. AWS manages servers and scaling.

  • Handler: function entry point.
  • Execution role: permissions used by the function.
  • Memory: also affects CPU allocation.
  • Timeout: maximum execution time.
  • Cold start: initialization delay for a new execution environment.
  • Layers: shared code or dependencies.
  • Destinations and DLQs: handle async success/failure outcomes.

Java angle: keep initialization efficient, reuse SDK clients outside the handler, size memory deliberately, and understand that package size and framework startup can affect cold starts.

Lambda Event Sources

API Gateway invokes Lambda for HTTP APIs. S3 can invoke Lambda on object events. DynamoDB Streams and Kinesis invoke Lambda with batches. SQS invokes Lambda from queues. EventBridge invokes Lambda on schedules or event patterns.

Exam trap: retry behavior depends on invocation type and event source. Async Lambda retries differ from stream retries and SQS visibility timeout behavior.

API Gateway

API Gateway exposes APIs to clients. It can integrate with Lambda, HTTP backends, AWS services, authorization, throttling, caching, stages, deployments, mapping templates, and custom domains.

  • REST API: feature-rich, older, supports many advanced controls.
  • HTTP API: simpler, lower latency/cost for common HTTP workloads.
  • WebSocket API: bidirectional client communication.

Common troubleshooting: 403 can be auth or resource policy; 429 is throttling; 502 often means integration failure; 504 means timeout.

SAM and CDK

SAM is a serverless-focused extension of CloudFormation. CDK lets you define cloud infrastructure using programming languages. SAM is concise for Lambda/API Gateway/DynamoDB serverless apps. CDK is broader and code-driven.

Integration and Messaging

The PDF includes AWS Integration and Messaging. This is where DVA-C02 tests decoupling, retries, asynchronous design, and event-driven architecture.

SQS

SQS is a queue. Producers send messages. Consumers poll messages. SQS decouples services and absorbs traffic spikes.

  • Standard queue: high throughput, at-least-once delivery, best-effort ordering.
  • FIFO queue: ordering and exactly-once processing behavior within the FIFO constraints.
  • Visibility timeout: time a message is hidden after a consumer receives it.
  • DLQ: stores messages that fail repeatedly.

Exam trap: if messages are processed more than once, your consumer must be idempotent. SQS standard queues can deliver duplicates.

SNS

SNS is pub/sub. One publisher can fan out events to multiple subscribers: SQS, Lambda, HTTP endpoints, email, or SMS. Use SNS when multiple consumers should react to the same event.

Kinesis

Kinesis is for streaming data. Records are distributed across shards by partition key. Ordering is guaranteed within a shard, not globally. Consumers process records from shards and checkpoint progress.

EventBridge

EventBridge routes events using rules and event buses. It is useful for SaaS integrations, AWS service events, scheduled events, and application event routing.

Step Functions

Step Functions orchestrates workflows. Use it when business logic spans multiple steps, needs retries, branching, waits, human approval, or compensation logic. It can coordinate Lambda, ECS, Batch, SNS, SQS, DynamoDB, and more.

Deployment

The PDF includes Elastic Beanstalk, CloudFormation, CodeCommit, CodeBuild, CodeDeploy, CodePipeline, SAM, and CDK. DVA-C02 expects you to understand deployment tools and safe release patterns.

CloudFormation

CloudFormation is infrastructure as code. A template declares resources and AWS creates, updates, or deletes them as stacks. Know parameters, mappings, outputs, change sets, drift detection, and rollback behavior.

CodeBuild

CodeBuild runs build jobs based on a buildspec.yml. It can compile Java, run tests, build Docker images, and publish artifacts.

phases:
  build:
    commands:
      - ./mvnw clean verify
      - docker build -t reservation-api:$CODEBUILD_RESOLVED_SOURCE_VERSION .

CodeDeploy

CodeDeploy deploys application revisions to EC2, Lambda, or ECS. It supports deployment strategies like in-place, blue/green, canary, and linear depending on target type.

CodePipeline

CodePipeline coordinates source, build, test, approval, and deploy stages. Think of it as the release workflow.

Elastic Beanstalk vs CloudFormation vs SAM vs CDK

  • Elastic Beanstalk: easiest managed app environment for web apps and workers.
  • CloudFormation: direct infrastructure-as-code service.
  • SAM: concise serverless IaC built on CloudFormation.
  • CDK: define AWS infrastructure using programming languages.

Monitoring and Troubleshooting

DVA-C02 troubleshooting is practical. You need to know where logs, metrics, traces, deployment events, and service errors appear.

CloudWatch

CloudWatch collects metrics, logs, alarms, dashboards, and events. Lambda logs go to CloudWatch Logs. Many services publish metrics automatically. Custom metrics let applications report business or technical signals.

X-Ray

X-Ray traces requests across services. It helps identify which downstream call is slow or failing. For distributed systems, traces are often the fastest way to understand where time is spent.

CloudTrail

CloudTrail records AWS API activity. If someone changed a security group, deleted a function, updated a policy, or called an AWS API, CloudTrail is the audit trail.

Common Exam Troubleshooting Patterns

  • AccessDenied: check IAM identity policy, resource policy, KMS key policy, boundaries, SCPs, and explicit denies.
  • Lambda timeout: check timeout value, VPC networking, downstream latency, memory/CPU sizing, and retries.
  • DynamoDB throttling: check partition key design, capacity mode, hot keys, retry with backoff, and GSIs.
  • API Gateway 5xx: check Lambda errors, permissions, integration timeout, mapping templates, and backend response format.
  • SQS duplicates: make consumers idempotent and tune visibility timeout.
